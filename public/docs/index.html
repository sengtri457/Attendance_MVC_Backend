Attendance System API

Welcome to the premium developer documentation for the Attendance tracking MVC network. This platform allows programmatic management of students, schedules, and real-time class verification.

🔐 Authentication Header

Most routes are heavily protected relying on modern JWT structures. Upon login, include this token via the header on every subsequent request.

HTTP Header Requirement Authorization: Bearer

1. Authentication Module

POST /api/v1/auth/login

Authenticate global user structures (students, teachers, admins) directly producing system-verified tokens.

Request Body Payload { "username": "admin01", "password": "securepassword123" } 200 OK Response { "success": true, "token": "eyJhbGciOiJIUz...", "user": { "user_id": 1, "role": "admin", "username": "admin01" } }

2. Student Registry

GET /api/v1/student/:id 🔒 Protected

Access complex underlying detail for specific students registered throughout varying database relations.

POST /api/v1/student/upload-excel 🔒 Protected

Initiate an immediate bulk insertion processing pipeline leveraging direct multipart/form-data uploading standards targeting a valid .xlsx roster file.

3. Attendance Core Operations

POST /api/v1/attendance/submit-batch 🔒 Protected

The foundational endpoint controlling sweeping end-of-class metrics. Accepts grouping of multi-student evaluations simultaneously—triggering automated fallback analytics and integrated Telegram relay dispatches effortlessly.

Request Body Payload { "teacher_id": 2, "subject_id": 8, "attendance_date": "2024-03-02", "session": "morning", "records": [ { "student_id": 1, "status": "P" }, { "student_id": 2, "status": "A", "notes": "Medical emergency" }, { "student_id": 3, "status": "L", "notes": "Traffic stall" } ] }
GET /api/v1/attendance/reports/dashboard 🔒 Protected

Dynamically resolves critical system thresholds supplying pre-calculated performance overviews mapped specifically for immediate high-level UI rending.
